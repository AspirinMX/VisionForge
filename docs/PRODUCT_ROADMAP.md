# 视频创作工坊：三阶段交付计划

更新日期：2026-11-18。状态：产品范围已确认；各项能力以代码、迁移和验收记录为准。

## 1. 产品目标与边界

VisionForge 是以对话驱动、以分镜组织、支持持续修改并交付成片的图片与视频创作工坊。用户可以从想法、脚本或已有素材开始，不要求必须经过固定的创作步骤。

产品始终遵守：创作可控制、修改可局部进行、任务可恢复、成本可核对、作品可追溯。

当前保留八模块架构及用户独立的会话归属模型。脚本、提示词、图片、视频属于当前会话；不新增工作空间、成员或默认跨会话共享。企业团队、SSO 和审核权限属于第三阶段的独立扩展，不改变首版隔离边界。

主对话和本地 compact 继续使用官方 OpenAI Java SDK 的 Responses SSE；主模型支持图片输入、文本输入和文本输出，图片以 `input_image` 内容块参与调用。媒体生成采用 `MEDIA_PIPELINE_DESIGN.md` 所述的协议适配器访问现有第三方网关。任务、归档、计费不因模型或协议改变而另建一套实现。媒体模型能力以配置和适配器实际支持情况共同决定，不按品牌名称猜测。

## 2. 第一阶段：单镜头创作闭环

目标：用户能够上传产品或角色图片，生成画面，将选定图片生成视频，比较、修改并下载结果；关闭页面后任务继续，返回后仍可查看完整历史和费用。

### 2.1 功能范围

| 领域 | 必须交付的业务能力 |
| --- | --- |
| 创作入口 | 登录、会话选择与创建、对话创意讨论；图片与视频快捷入口复用同一业务服务 |
| 素材 | 上传图片、校验媒体、发布为会话文件；预览和下载；固定素材版本作为生成输入 |
| 模型能力 | 文本、图片、视频模型分离；协议、输入角色、规格和价格可配置；前后端共同拒绝不支持的参数 |
| 图片 | 文生图、按已接入协议提供参考图编辑；保存实际提示词、参数、输入与输出 |
| 视频 | 文生视频、首帧图生视频；首尾帧仅在模型明确支持时开放；持久化远端任务并轮询 |
| 候选与修改 | 同一需求的候选结果可比较；复用参数和素材生成新候选；新任务关联原任务，保留旧结果 |
| 任务中心 | 按会话查看任务及详细阶段、结果与错误；请求取消、单独恢复归档；断线后读取持久化状态 |
| 交付与来源 | 结果进入对象存储和会话文件；图片预览、视频播放和下载；可查询来源任务、输入版本及模型参数 |
| 预算和费用 | 提交前展示估算；额度预占、交付结算、取消释放和待核账；账本防重；价格快照不受后续调价影响 |
| 运维与隔离 | 模型管理、额度管理、任务诊断；他人资源和同用户其他会话素材不可引用；管理员不自动获得用户内容权限 |

首版每个付费任务请求一个输出；多次生成形成候选集合，避免把供应商组图差异暴露为统一承诺。视频声音和编辑能力按模型能力开放。复杂剪辑、多镜头调度、自动发布、团队共享不属于本阶段。

### 2.2 状态与收费规则

- 区分待提交、提交中、上游运行、归档中、已交付、失败、取消和结果未知；取消请求与最终取消结论分别保存。
- 付费提交不盲目重试；提交结果未知保留预占并进入核对。浏览器断线和 AgentRun 结束不取消媒体任务。
- 已获得产物但保存失败，只重试归档、发布与结算，不重新生成。已有远端任务 ID 时继续查询该任务。
- 用户按可交付产物结算；确认失败或提交前取消释放预占；已产生的供应商成本独立留档，未知成本不伪造为零。
- API 同幂等键、同请求返回原任务；同键不同请求返回 409。“再生成”使用新键和新任务。

### 2.3 验收标准

1. 从上传参考图到生成图片、选用图片生成视频、播放与下载形成完整流程；用户能独立找到相应入口。
2. 修改提示词或参数后创建新候选，旧产物、原始输入、冻结素材版本和费用记录继续可查。
3. 重复提交、Workflow 启动补偿、Activity 重放不会重复付费提交、发布文件或扣费。
4. 供应商接单但本地响应丢失进入结果未知；取消与完成竞态不使任务状态回退。
5. 对象存储故障后只恢复交付步骤；刷新页面、Redis 故障或对话结束不会丢失任务。
6. 不支持的模型参数在付费前拒绝；余额不足拒绝受理；并发任务不能超额预占。
7. API、工具、文件、资产与下载均验证用户和会话归属；权限测试、工作流测试及迁移验证通过。
8. 前端 lint/build、后端测试通过；离线供应商桩验证请求、轮询、归档与收费。真实付费网关联调与离线验证分开记录，不把离线通过描述为生产接入已验证。

## 3. 第二阶段：多镜头生产闭环

目标：用户制作一条多镜头短片，固定人物、产品和风格，仅重做不满意的镜头，并导出成片。

| 领域 | 交付范围 |
| --- | --- |
| 创作简报 | 用途、受众、渠道、画幅、时长、语言、风格、品牌要求和总预算；变更提示受影响内容 |
| 脚本和分镜 | 剧本使用 Markdown，分镜使用结构化 JSON；镜头画面、对白、景别、运镜、时长、声音和引用素材；增删、拆分、合并和排序；文件版本复用现有模型 |
| 一致性素材 | 角色多角度、服装、场景、产品和风格设定；镜头引用固定版本；不承诺模型输出绝对一致 |
| 镜头制作 | 批量生成、依赖调度、候选选择、锁定已确认镜头、局部重做和质量复核 |
| 轻量编排 | 镜头排序、片段裁剪、简单转场、整片预览；避免首版即引入完整专业剪辑器 |
| 声音与字幕 | 旁白、对白、背景音乐、音效、字幕时间轴、音量及淡入淡出；来源与权限可追踪 |
| 成片交付 | 保存成片版本，导出视频、封面、字幕和素材包；成片追溯到镜头及其生成记录 |

验收：至少一条多镜头短片完成“简报—脚本—分镜—逐镜头生成—选用—编排—导出”；替换一个镜头保留其他镜头和旧成片版本；批量任务受总预算限制，部分失败可以局部恢复。

### 2.1 已确认的创作数据格式

- 剧本：Markdown，保存为会话文件 `SCRIPT`。
- 分镜：结构化 JSON，保存为会话文件 `STORYBOARD`；字段、枚举和版本规则见 `PROPOSAL.md` §13.2。
- 主模型：支持图片输入、文本输入、文本输出；本轮消息附带的图片以 `input_image` 参与调用，历史图片默认不重复回放。

## 4. 第三阶段：规模化生产与企业治理

目标：可重复生产多语言、多渠道、多版本作品，并建立授权、质量和成本治理。

| 领域 | 交付范围 |
| --- | --- |
| 创作模板 | 固定流程、镜头结构、品牌规范与变量；版本化模板及运行记录 |
| 批量变体 | 按产品、文案、语言、画幅和发布渠道生成变体；配额、优先级及批次成本 |
| 质量检查 | 人物与产品一致性、异常画面、字幕、音轨、规格和镜头衔接检查；人工复核与结果解释 |
| 团队治理 | 独立设计组织、角色、素材授权、审核、发布、部门预算、SSO 与审计；显式迁移首版归属模型 |
| 企业运营 | 使用报表、供应商成本核对、异常处理队列、留存和清理、备份恢复及容量管理 |

验收：同一模板可受控地批量生产并追溯每个变体的输入、版本、审核和费用；权限不会因模板或共享扩大；失败批次可定位、局部恢复并核账。
