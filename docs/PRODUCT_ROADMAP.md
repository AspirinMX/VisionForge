## 1. 产品目标与边界

VisionForge 是以对话驱动、以分镜组织、支持持续修改并交付成片的图片与视频创作工坊。用户可以从想法、脚本或已有素材开始，不要求必须经过固定的创作步骤。

产品始终遵守：创作可控制、修改可局部进行、任务可恢复、成本可核对、作品可追溯。

默认行为与直接工具并存：

- 用户提出“生成一条短片/广告”这类成片请求时，主 Agent 默认执行五步流程：写剧本、写分镜、逐镜生成首帧图、逐镜生成视频候选、按分镜顺序合成成片。
- 用户只要一张图片、一个已有首帧的片段或单独修改某一步时，可以直接调用相应工具，不强制补全前序步骤。
- 五步是成片请求的默认路径，不是所有请求的固定流水线；动态 Agent Loop 仍然成立。

当前保留八模块架构及用户独立的会话归属模型。脚本、提示词、图片、视频属于当前会话；不新增工作空间、成员或默认跨会话共享。企业团队、SSO 和审核权限属于第三阶段的独立扩展，不改变首版隔离边界。

主对话和本地 compact 继续使用官方 OpenAI Java SDK 的 Responses SSE；主模型支持图片输入、文本输入和文本输出，图片以 `input_image` 内容块参与调用。媒体生成采用 `MEDIA_PIPELINE_DESIGN.md` 所述的协议适配器访问现有第三方网关。任务、归档、计费不因模型或协议改变而另建一套实现。媒体模型能力以配置和适配器实际支持情况共同决定，不按品牌名称猜测。

## 2. 第一阶段：成片创作闭环（单镜头 + 多镜头顺序合成）

目标：用户能够从一句话或已有素材开始，生成单张图片、单条视频，或按分镜顺序生成多镜头短片并导出成片；能比较候选、只重做某个镜头、查看完整历史和费用；关闭页面后本轮等待的生成任务继续，返回后仍可看到结果。

### 2.1 功能范围

| 领域 | 必须交付的业务能力 |
| --- | --- |
| 创作入口 | 登录、会话选择与创建、对话创意讨论；图片与视频快捷入口复用同一业务服务 |
| 剧本 | 从一句话提取主体、事件、目标时长；补全场景、角色和可见动作；保存 `SCRIPT` Markdown，修改产生新版本 |
| 分镜 | 一次写出整组镜头；每镜记录首帧画面、后续动作、镜头衔接、时长、运镜、参考素材和选中输出；保存 `STORYBOARD` JSON，`shotId` 稳定可追踪 |
| 素材 | 上传图片、校验媒体、发布为会话文件；预览和下载；固定素材版本作为生成输入 |
| 模型能力 | 文本、图片、视频模型分离；协议、输入角色、规格和价格可配置；前后端共同拒绝不支持的参数 |
| 图片 | 文生图、按已接入协议提供参考图编辑；分镜首帧图归属具体镜头；保存实际提示词、参数、输入与输出 |
| 视频 | 文生视频、首帧图生视频；一次调用为一个镜头生成一个候选片段；首尾帧仅在模型明确支持时开放；持久化远端任务并轮询 |
| 同 run 等待 | 依赖产物时，当前 AgentRun 持久化等待图片或视频交付，再把结果交回同一主模型；不让模型反复查询进度，不阻塞工具 Activity |
| 候选与修改 | 同一镜头或同一需求的候选可比较；复用参数和素材生成新候选；重做某个镜头只影响该镜头；新任务关联原任务，保留旧结果 |
| 顺序成片 | 按分镜顺序读取所选片段和使用区间，完成裁剪、规格统一与拼接；输入引用 S3 已有片段，输出为新成片资产写回 S3；保留原始片段与旧成片版本 |
| 任务中心 | 按会话查看任务及详细阶段、结果与错误；请求取消、单独恢复归档；断线后读取持久化状态 |
| 交付与来源 | 结果进入对象存储和会话文件；图片预览、视频播放、成片下载；可查询来源任务、输入版本、模型参数和所用镜头 |
| 预算和费用 | 提交前展示估算；额度预占、交付结算、取消释放和待核账；账本防重；价格快照不受后续调价影响；成片合成本身不按模型调用计费 |
| 运维与隔离 | 模型管理、额度管理、任务诊断；他人资源和同用户其他会话素材不可引用；管理员不自动获得用户内容权限 |

首版每个付费模型任务请求一个输出；多次生成形成候选集合，避免把供应商组图差异暴露为统一承诺。视频声音和编辑能力按模型能力开放。本阶段只做**顺序合成**：排序、裁剪、规格统一、拼接；复杂转场、多轨、字幕时间轴、自动发布、团队共享不属于本阶段。

### 2.2 成片请求的默认五步流程

| 环节 | 主 Agent 怎样做 | 保存和交付什么 | 等待语义 |
| --- | --- | --- | --- |
| 1. 剧本 | 从用户一句话中提取主体、事件、目标时长等明确要求，补全场景、角色和可见动作。例如“橘猫第一次出门”写成“缩爪、试探、跨过门槛” | 当前会话保存一份 `SCRIPT` Markdown；后续修改产生新版本 | 不涉及生成任务 |
| 2. 分镜 | 通读剧本，一次写出整组镜头。每镜明确：第一帧看见什么、随后发生什么、这一镜怎样接上前后镜 | 保存一份 `STORYBOARD` JSON；`shots[]` 按 `order` 播放，稳定 `shotId` 追踪素材；每镜记录时长、画面、运镜、参考素材和选中的输出 | 不涉及生成任务 |
| 3. 分镜首帧图 | 用全片角色和风格设定、该镜首帧描述以及已有参考图调用图片工具，等待得到可用图片资产 | 每张首帧图归属具体镜头，保存 assetId 和版本；相邻镜头可以共用角色参考图，各自保留独立构图 | 当前 run 等到图片交付后继续 |
| 4. 分镜视频 | 一次 `generate_video` 为一个镜头生成一个候选片段；输入是该镜首帧图、动作与运镜描述、时长等参数 | 每镜保存视频候选和选用结果；用户要求重做第二镜时，只为第二镜再生成一个候选 | 当前 run 等到片段交付后继续 |
| 5. FFmpeg 成片 | 按分镜顺序读取所选片段和使用区间，完成裁剪、规格统一与拼接 | 输入引用 S3 中已有的片段，输出作为新的成片资产写回 S3；保留原始片段和旧成片，能够追溯本版用了哪些镜头 | 成片任务完成后再交付 |

这里的“分镜”是第 2 步生成的拍摄描述，“分镜视频”是第 4 步生成的可播放片段，两者靠首帧资产衔接。例如第二镜要拍“猫爪落进浅水”，首帧生图描述应是“爪尖悬在水面上方”，视频描述才是“爪尖落下，水面泛起涟漪”。首帧字段和视频字段必须分开传给两个工具。

### 2.3 状态与收费规则

- 区分待提交、提交中、上游运行、归档中、已交付、失败、取消和结果未知；取消请求与最终取消结论分别保存。
- 付费提交不盲目重试；提交结果未知保留预占并进入核对。浏览器断线和 AgentRun 结束不取消媒体任务。
- 依赖产物时，AgentRun 通过工具层的持久化等待推进；等待中的 run 不阻塞其他会话，也不取消已受理的媒体任务。
- 已获得产物但保存失败，只重试归档、发布与结算，不重新生成。已有远端任务 ID 时继续查询该任务。
- 用户按可交付产物结算；确认失败或提交前取消释放预占；已产生的供应商成本独立留档，未知成本不伪造为零。
- API 同幂等键、同请求返回原任务；同键不同请求返回 409。“再生成”使用新键和新任务。
- 成片合成是本地媒体处理任务，不产生模型调用费用；其存储占用和失败恢复按媒体资产规则处理。

### 2.4 验收标准

1. 从上传参考图到生成图片、选用图片生成视频、播放与下载形成完整流程；用户能独立找到相应入口。
2. 修改提示词或参数后创建新候选，旧产物、原始输入、冻结素材版本和费用记录继续可查。
3. 重复提交、Workflow 启动补偿、Activity 重放不会重复付费提交、发布文件或扣费。
4. 供应商接单但本地响应丢失进入结果未知；取消与完成竞态不使任务状态回退。
5. 对象存储故障后只恢复交付步骤；刷新页面、Redis 故障或对话结束不会丢失任务。
6. 不支持的模型参数在付费前拒绝；余额不足拒绝受理；并发任务不能超额预占。
7. API、工具、文件、资产与下载均验证用户和会话归属；权限测试、工作流测试及迁移验证通过。
8. 前端 lint/build、后端测试通过；离线供应商桩验证请求、轮询、归档与收费。真实付费网关联调与离线验证分开记录，不把离线通过描述为生产接入已验证。
9. 一句话成片请求能够走通“剧本—分镜—首帧图—分镜视频—FFmpeg 成片”，最终得到可播放成片；剧本、分镜、每镜首帧、视频候选、选中片段和成片版本可相互追溯。
10. 当前 AgentRun 在需要图片或视频产物时持久化等待，产物就绪后继续同一轮模型；不通过反复调用查询工具消耗 token，也不在工具 Activity 内阻塞整个生成时长。
11. 用户要求重做第二镜时，只新增第二镜候选；其他镜头、选中结果和旧成片版本保持不变。
12. 成片合成从 S3 读取所选片段，按使用区间裁剪、统一规格并拼接；失败执行 multipart 撤销，成功后发布新成片资产，原始片段不被删除。
13. 真实图片/视频协议适配、离线契约验证和真实网关联调分别记录状态；没有上游测试条件时只能标记“适配已实现”，不能标记“联调通过”。

### 2.5 已确认的创作数据格式

- 剧本：Markdown，保存为会话文件 `SCRIPT`。
- 分镜：结构化 JSON，保存为会话文件 `STORYBOARD`；字段、枚举和版本规则见 `PROPOSAL.md` §13.2。
- 主模型：支持图片输入、文本输入、文本输出；本轮消息附带的图片以 `input_image` 参与调用，历史图片默认不重复回放。

## 3. 第二阶段：多镜头生产增强

目标：在顺序成片闭环之上，加入创作简报、一致性素材、批量制作、声音字幕和更强的编排能力，固定人物、产品和风格，仅重做不满意的镜头。

| 领域 | 交付范围 |
| --- | --- |
| 创作简报 | 用途、受众、渠道、画幅、时长、语言、风格、品牌要求和总预算；变更提示受影响内容 |
| 脚本和分镜增强 | 基于第一阶段 Markdown 剧本和 JSON 分镜，增加拆分/合并/排序、版本比较、受影响镜头提示 |
| 一致性素材 | 角色多角度、服装、场景、产品和风格设定；镜头引用固定版本；不承诺模型输出绝对一致 |
| 镜头制作 | 批量生成、依赖调度、候选选择、锁定已确认镜头、局部重做和质量复核 |
| 编排增强 | 更细的片段裁剪、简单转场、整片预览；仍避免引入完整专业剪辑器、多轨时间线和无限画布 |
| 声音与字幕 | 旁白、对白、背景音乐、音效、字幕时间轴、音量及淡入淡出；来源与权限可追踪 |
| 成片交付增强 | 保存成片版本，导出视频、封面、字幕和素材包；成片追溯到镜头及其生成记录 |

验收：至少一条多镜头短片完成“简报—脚本—分镜—逐镜头生成—选用—编排增强—声音字幕—导出”；替换一个镜头保留其他镜头和旧成片版本；批量任务受总预算限制，部分失败可以局部恢复。

### 3.1 已确认的创作数据格式

第一阶段已经确定的剧本 Markdown、分镜 JSON 和主模型多模态输入规则在第二阶段继续复用，不另建第二套事实来源。

## 4. 第三阶段：规模化生产与企业治理

目标：可重复生产多语言、多渠道、多版本作品，并建立授权、质量和成本治理。

| 领域 | 交付范围 |
| --- | --- |
| 创作模板 | 固定流程、镜头结构、品牌规范与变量；版本化模板及运行记录 |
| 批量变体 | 按产品、文案、语言、画幅和发布渠道生成变体；配额、优先级及批次成本 |
| 质量检查 | 人物与产品一致性、异常画面、字幕、音轨、规格和镜头衔接检查；人工复核与结果解释 |
| 团队治理 | 独立设计组织、角色、素材授权、审核、发布、部门预算、SSO 与审计；显式迁移首版归属模型 |
| 企业运营 | 使用报表、供应商成本核对、异常处理队列、留存和清理、备份恢复及容量管理 |

验收：同一模板可受控地批量生产并追溯每个变体的输入、版本、审核和费用；权限不会因模板或共享扩大；失败批次可定位、局部恢复并核账。
